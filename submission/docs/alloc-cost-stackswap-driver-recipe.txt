BLOCKER (exact): `wordPathWork_call_exception_at` requires
  hmidT : middleT = { middle with stack := st }
but the packet's exception clause (Props/EvaluateStackSwap/Motive.lean:88-105) rebuilds the
transported middle's locals from the *transported* frame payload:
  E xs = (some (.exception x y), { s1 with stack := st, handler := n.1, locals := locs })
  locs = sptUnion (sptFromAList lss') (sptFromAList e0'), lss.map snd = lss'.map snd,
  e'.map fst = lss'.map fst
i.e. the transported locals agree with the source locals in *values* but carry the
transported (SSA-renamed) *keys*.  With only `sValEq s.stack xs` as hypothesis, lss' keys are
unconstrained, so `middleT.locals = middle.locals` is NOT derivable, and the same handlerCode
run at two locals differing in keys can have different wordPathWork cost => the exception arm
(and hence `.call` for handlers != none) is not derivable from sValEq alone.

FIX (recommended, one-line change of hypothesis, propagation already available): carry
  hkey : sKeyEq s.stack xs
alongside hval through the induction.  Then the packet's ∀ can be instantiated at the actual
frames and lss' = lss (keys from e'.map fst = e.map fst = lss.map fst, values from
lss.map snd = lss'.map snd) => locs = middle.locals => hmidT holds => _exception_at applies.
Propagation to recursive calls is free: the generic clause returns `sKeyEq xs st` for the
child state, and `.seq`/`.ite`/`.loop` already thread the state's stack unchanged.
